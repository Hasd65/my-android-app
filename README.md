# BT Bridge 2.0 — мост уведомлений и данных между Android и Wear OS

Приложение из двух частей: телефон и часы. Работает **без сервисов Google**,
без аккаунтов и без интернета. Связь — BLE GATT напрямую между устройствами.

---

## Что делает

| Функция | Телефон | Часы |
|---|---|---|
| Перехват уведомлений | ✓ `NotificationListenerService` | — |
| Передача на часы | ✓ BLE GATT-клиент | ✓ BLE GATT-сервер |
| Показ сообщений | — | ✓ карточка + вибрация + пробуждение экрана |
| История | — | ✓ до 50 записей |
| Пульс | ✓ приём и хранение | ✓ `TYPE_HEART_RATE` |
| Шаги | ✓ сумма за день | ✓ `TYPE_STEP_COUNTER` |
| Диагностика | ✓ статус канала | ✓ статус + счётчики |

---

## Требования

- Телефон: Android 11+ (API 30), Bluetooth LE.
- Часы: Wear OS 3+ (API 30), Bluetooth LE.
- Оба устройства: разрешения Bluetooth, для часов — доступ к датчикам.
- **Сопряжение (pairing) НЕ требуется.** BLE GATT работает без bond.

## Как собрать APK

### Вариант 1: Android Studio (проще)

1. Установите Android Studio (любая свежая версия).
2. `File → Open` → выберите папку `app` (там где `settings.gradle.kts`).
3. Дождитесь синхронизации Gradle (первый раз качает зависимости, 5–15 минут).
4. Меню `Build → Build App Bundle(s) / APK(s) → Build APK(s)`.
5. Готовые файлы:
   - `phone/build/outputs/apk/debug/phone-debug.apk`
   - `watch/build/outputs/apk/debug/watch-debug.apk`

### Вариант 2: командная строка

```bash
cd app
gradle wrapper --gradle-version 8.11.1   # один раз, создаёт gradlew
./gradlew :phone:assembleDebug :watch:assembleDebug
```

На Windows: `gradlew.bat :phone:assembleDebug :watch:assembleDebug`

### Вариант 3: GitHub Actions (без установки чего-либо)

1. Загрузите папку `app` в репозиторий GitHub.
2. Workflow `.github/workflows/build.yml` соберёт оба APK автоматически.
3. Скачайте артефакты `phone-apk` и `watch-apk` со страницы Actions.

## Как установить

### Часы

```bash
adb connect <IP_часов>:5555
adb -s <IP_часов>:5555 install -r watch-debug.apk
```

IP часов: Настройки → Система → О телесе → нажать 7 раз на «Номер сборки» →
Для разработчиков → Отладка по Wi-Fi.

Или через Android Studio: выберите часы в списке устройств и нажмите Run.

### Телефон

```bash
adb install -r phone-debug.apk
```

Или скопируйте APK на телефон и откройте (разрешите установку из неизвестных источников).

## Настройка (по шагам)

### 1. Часы

1. Откройте **BT Bridge** на часах.
2. Разрешите все запросы (Bluetooth, уведомления, датчики).
3. Нажмите **Запустить**. Статус должен стать «ожидание».
4. Если статус «ошибка BLE» — проверьте, что Bluetooth включён.

### 2. Телефон

1. Откройте **BT Bridge**.
2. Нажмите **Запустить мост**.
3. Приложение попросит доступ к уведомлениям — нажмите **Открыть настройки**
   и включите «BT Bridge — перехват уведомлений» в списке.
4. Вернитесь в приложение. Статус должен смениться на «подключено: ...».
5. Проверьте: придите себе сообщение в мессенджер — оно должно появиться на часах.

### 3. Важно для ColorOS / китайских прошивок

Прошивка агрессивно убивает фоновые приложения. Сделайте:

1. Настройки → Приложения → BT Bridge → **Батарея** → **Без ограничений**.
2. Настройки → Приложения → BT Bridge → **Автозапуск** → включить.
3. Настройки → Приложения → BT Bridge → **Разрешить фоновую активность** → включить.
4. Экран недавних приложений → закрепите BT Bridge (замок).

Без этих шагов связь будет рваться через несколько минут после блокировки экрана.

## Как это работает

```
Телефон                                  Часы
┌─────────────────────────┐              ┌──────────────────────────┐
│ NotificationListener     │              │ BleServer (GATT)         │
│         ↓                │              │         ↓                │
│ Msg.notify() → JSON      │              │ FrameReader → Msg.parse  │
│         ↓                │   BLE GATT   │         ↓                │
│ Proto.frame() → 4б+JSON  │ ───────────► │ история / карточка /     │
│         ↓                │  CHAR_TO_WATCH│ вибрация / экран        │
│ BleClient.queue          │              │         ↓                │
│         ↓                │  CHAR_TO_PHONE│ Msg.ack()               │
│ ACK ←────────────────────┼──────────────┤                          │
└─────────────────────────┘              └──────────────────────────┘
```

### Протокол

- Кадр: 4 байта длины (big-endian) + UTF-8 JSON, максимум 4000 байт.
- `MSG_NOTIFY` — уведомление (id, app, title, text, at, pkg).
- `MSG_HEALTH` — показание (kind, v, u, at).
- `MSG_ACK` / `MSG_PING` / `MSG_PONG` / `MSG_HELLO`.
- Текст обрезается под MTU: заголовок 400 байт, тело 1600 байт.

### Почему GATT, а не RFCOMM

RFCOMM/SPP на Wear OS не гарантирован, его наличие на OnePlus Watch 3 не подтверждено.
BLE GATT доступен на любом Android 8+, не требует сопряжения и работает,
даже если Bluetooth-пара удалена.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «часы не найдены» | часы не запущены, BLE выключен | запустить приложение на часах, проверить Bluetooth |
| «сервис не найден» | на часах другая версия | переустановить оба APK из одной сборки |
| «нет разрешений Bluetooth» | отказ в доступе | Настройки → Приложения → разрешения |
| Уведомления не идут | нет доступа к уведомлениям | включить в Настройки → Специальные возможности → Доступ к уведомлениям |
| Связь рвётся через минуты | ColorOS убивает сервис | «Без ограничений» + автозапуск (см. выше) |
| Пульс не приходит | нет датчика или разрешения | проверить BODY_SENSORS, наличие датчика |

Логи:

```bash
adb logcat -s BtBridgeClient:V BtBridgeGatt:V BtBridgePhoneSvc:V BtBridgeWatchSvc:V
```

## Ограничения (честно)

1. **Это не замена OHealth.** Сон, SpO2, ЭКГ, AFib — не реализованы и не будут:
   они используют закрытые алгоритмы OPPO.
2. **Пульс и шаги — сырые данные с датчиков**, без обработки и без медицинской точности.
3. **Один телефон — одни часы.** Мультиподключение не поддерживается.
4. **APK подписаны debug-ключом.** Для личного использования этого достаточно,
   для публикации нужен свой keystore.
5. **Приложение не проверено на реальном устройстве.** Код написан и статически
   проверен, но запуск на OnePlus Watch 3 и Ace 3 Pro ещё предстоит.

## Структура проекта

```
app/
├── common/                     общий протокол для обеих сторон
│   ├── Proto.kt                UUID, константы, кадрирование
│   ├── Msg.kt                  сборка/разбор JSON-сообщений
│   └── FrameReader.kt          сборка кадров из фрагментов BLE
├── phone/
│   ├── BleClient.kt            GATT-клиент, очередь, переподключение
│   ├── BridgeService.kt        foreground-сервис
│   ├── NotificationRelayService.kt  перехват уведомлений
│   ├── HealthStore.kt          хранение показаний
│   ├── MainActivity.kt         UI
│   └── Prefs.kt                настройки
└── watch/
    ├── BleServer.kt            GATT-сервер, реклама
    ├── WatchService.kt         foreground-сервис
    ├── SensorCollector.kt      пульс и шаги
    ├── HistoryStore.kt         история сообщений
    ├── MainActivity.kt         UI
    ├── WakeActivity.kt         экран при сообщении
    └── VibratorHelper.kt       вибрация
```

## Что делать, если не работает

1. Соберите логи с обеих сторон:
   ```bash
   adb logcat -c
   # воспроизведите проблему
   adb logcat -d > phone.log
   adb -s <IP_часов>:5555 logcat -d > watch.log
   ```
2. Проверьте, что оба APK собраны из этой же папки (версии протокола должны совпадать).
3. Пришлите `phone.log` и `watch.log` — по ним видно, на каком шаге обрыв.
